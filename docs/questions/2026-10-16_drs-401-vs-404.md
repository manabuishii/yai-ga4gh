**Title:** Which status should a DRS server return when an invalid credential is sent for a non-existent object: 401 or 404?

**Body:**

Hello, I am implementing a DRS 1.5.0 server for learning purposes and could not find guidance on the precedence between `401` and `404`.

GetObject, PostObject, GetAccessURL and PostAccessURL all list `401`, `403` and `404` as possible responses (e.g. `openapi/paths/objects@{object_id}.yaml`, lines 42–46 and 70–74 at `drs-1.5.0`), described only as "The request is unauthorized." and "The requested `DrsObject` wasn't found." The Auth section says the implementation is responsible for defining and enforcing the authorization policy, but does not say in which order a server should evaluate the request.

The case I am unsure about:

- the client sends a credential that fails validation (expired Bearer token, a Passport with a bad signature, etc.), and
- the `object_id` does not exist.

Two orders seem reasonable:

1. **Credentials first:** validate any supplied credential (`401` if invalid) → look up the object (`404` if missing) → apply the object's policy (`401` if a required credential is missing, `403` if insufficient).
2. **Existence first:** look up the object (`404` if missing) → validate credentials → apply the policy.

Order 1 never silently ignores a broken credential, which helps clients notice expired tokens. Order 2 matches a reading of "not found means not found regardless of auth". In both orders a client without any credential can already tell whether an ID exists (it gets `404` vs `401`/`403`), so neither order hides existence on its own.

Questions:

1. Is there an intended order, or is it deliberately left to implementations?
2. If it is left to implementations, would it be worth a sentence in the Auth section, so that clients (and compliance tests) do not depend on one behaviour?
3. Relatedly, should a server that wants to hide the existence of protected objects return `404` instead of `403` for authenticated-but-unauthorized requests? The OpenAPI lists both, so I assume both are allowed.

For reference, my implementation uses order 1. Thank you!
